# ADR-0012: Testing GPU and codec features in CI

- **Status:** Proposed. Pending spike S6 (2026-11-17)

## Context
Cloud CI has no GPU and no hardware codecs. Research notes:
- Headless Chromium needs explicit flags for WebGPU; on Linux it falls back to the SwiftShader software rasteriser, which can be very slow
  for heavy scenes, and WebGPU canvas screenshots can come back black in headless mode ([Chrome blog](https://developer.chrome.com/blog/supercharge-web-ai-testing)).
- Whether `VideoEncoder`/`VideoDecoder` work in headless Chromium on Linux is **unverified** (one forum report says no). Also, Playwright's
  bundled Chromium may lack proprietary codecs (H.264/AAC); the branded Chrome channel may be needed. Both must be probed, not assumed.

## Decision (proposed)
1. **Unit tests (Vitest):** document model, commands, undo/redo, migrations, timeline maths, capability logic. No browser needed. This is the bulk of the suite.
2. **Browser tests (Playwright):** run in real Chromium. We target WebGL2 (not WebGPU) so software rendering is a valid CI path.
3. **Render regression:** golden images with a tolerance threshold. Golden files are generated by the CI renderer; real-GPU output is verified manually and via spikes.
4. **Codec tests:** run where the spike proves encoders exist (likely a `windows-latest` runner and/or the Chrome channel); skipped with an explicit marker (not silently) where unsupported.
5. **Cross-browser:** Firefox and WebKit run capability-detection and smoke tests only.
6. **Exports are tested end to end**: encode a short fixture, re-open the output with the decoder, check duration, frame count, resolution and audio presence.
7. **Fixtures:** tiny generated or CC0 media only. Never commit real user media (repo rule).

## Consequences
- CI cannot prove hardware-encode behaviour; that stays a manual checklist per release on real machines (Iris Xe available locally).

## Spike findings (2026-11-17, see ../research/spike-results.md)
- S6: on the owner's Windows + Iris Xe machine, **headless branded Chrome 157 has working `VideoEncoder` (H.264 hardware and software, VP9), AAC and Opus, and hardware-backed WebGL2/WebGPU**. Edge behaved the same.
- **Not verified:** Linux and GitHub Actions runners. The probe and the command to run it there are in `spikes/results/s6-probe.md`. Until that is run, the codec-test plan (branded Chrome channel, Windows runner first) is a plan, not a proven fact.
- Playwright's bundled Chromium was not tested; only the branded Chrome and Edge executables were.
